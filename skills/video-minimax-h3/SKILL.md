# MiniMax H3 参考生视频提示词技能

适用于 MiniMax H3 的多模态参考生成（Ref2VA）：每个镜头带若干张参考图，提示词用 `<Picture N>` 指代第 N 张参考图。
任务：把已有的 h3Prompt 改写成可以直接提交的英文提示词。只改写，不创作新剧情。

## 不可改动的内容（程序会逐项检查，违反就废弃本次改写）

1. 每个 `<Picture N>` 是参考图编号：编号、写法、出现次数、先后顺序都不变。不新增、不合并、不翻译、不重新编号。
2. `<d>...</d>` 台词块逐字复制，包括里面的语言标签。不翻译、不润色。
3. `[Shot k]` 镜头标记和切点时间（如 `00:05.000`）保留，顺序不变。
4. `<d>` 之外全部写成英文。
5. 不新增人物、道具、剧情、旁白、字幕和画面文字；不新增原提示词没有的风格标签。

## 写法（学习自 minimax-h3-video-prompt）

把提示词当成导演指令，不是审美描述。按六层控制检查每个镜头：

| 层 | 要写清什么 |
|---|---|
| 不变量 | 什么不能漂移：人物身份、服装、关键道具、场景布局 |
| 事件 | 实际发生什么：动作顺序、对象关系、状态变化、结束时的画面 |
| 摄影 | 景别、机位、构图、运镜、对焦、切镜，并绑定到主体的行为 |
| 质感 | 光线、色彩、材质；只写能落到画面上的 |
| 声音 | 对白、音乐、环境声、动作音效，各自归属清楚 |
| 目的 | 这一镜负责识别主体、推进冲突还是收束情绪 |

具体规则：

- **参考图职责。** 第一次出现 `<Picture N>` 时就让它的职责清楚：谁的身份、服装、场景还是道具。不让两张图竞争同一个核心身份。不在每个镜头重复描述整套参考图的外观。
- **一个镜头一个主任务。** 每个 `[Shot k]` 只有一个主要动作、一个镜头意图和一个转场出口。动作数量要能在该镜头的时长内完成。
- **摄影词绑定行为。** 写「the camera pushes in slowly as <Picture 1> loses balance」，不写「cinematic close-up」。同一镜头里不同时要求固定机位、环绕和手持抖动。
- **转场写触发物。** 写遮挡、动作匹配、声音重拍，不写「smooth transition」。
- **声音分层。** 对白、非叙事配乐、环境声、动作音效分开写；原提示词没有旁白就不加。
- **删除空话。** 去掉不能落到光线、材质、色彩或摄影行为的形容词；否定词只保留高概率、高损失的错误，不堆砌。
- **长度。** 够用即可，不重复主体描述和风格词。总长不超过 7000 字符。
- **不写占位语。** 不出现「可自行补充」「大概如此」「参考类似效果」这类句子。

## 保持原结构

h3Prompt 如果带有对齐行、`[Shot k]` 段、整体音景、非叙事配乐这些部分，改写后仍按原顺序保留，只改写其中的文字。

## 时间轴

- 分段首尾连续覆盖目标时长，不越界、不倒序。
- 切点时间以原提示词为准，不重算。
- 提示词里出现的任何时间区间，结束时间不超过该镜头的目标时长。

## 官方限制（2026-08-01）

- 提示词不超过 7000 字符；时长 4—15 秒且只接受整数。
- 多模态参考入口：图片最多 9 张；图片、视频、音频合计最多 12 个文件。
- 使用 ComfyUI 工作流时，参考图槽位数以工作流为准（本项目默认 `max_refs`）。

## 输出

只输出最终提示词：不解释、不加 Markdown、不加标题、不加前后引号。
