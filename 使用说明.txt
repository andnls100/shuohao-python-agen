================================================================
视频生成重新设计：从文生视频改为图生视频（方案，尚未实现）
================================================================

一、为什么要改

现状：视频阶段只把分镜的 h3Prompt（或 Seedance 拼接提示词）当文字发给视频模型，
没有传任何图片。同一角色、同一场景在不同分段里每次都由模型凭文字重新想象，
所以外观、服装、空间布局会漂移。文字再详细也压不住这一点。

结论：一致性要靠"图"来锁定，视频模型只负责让图动起来。

二、已核实的事实（来自智谱开放平台官方文档，设计以此为界）

1. CogVideoX-3 支持三种输入：文生视频、图生视频、首尾帧生视频。
2. image_url：URL 或 Base64；格式 png/jpeg/jpg；单张不超过 5MB。
   传 1 张是首帧；传 2 张时第一张是首帧、第二张是尾帧。
3. 首尾帧模式只支持 quality=speed。
4. prompt 最多 512 字符；时长只能 5 或 10 秒；size 取固定几档。
5. with_audio 只生成 AI 音效，文档没有承诺台词和口型。
6. 同一个接口还提供 Vidu 系列：viduq1-image、vidu2-image（图生，1 张首帧）、
   viduq1-start-end、vidu2-start-end（首尾帧）、vidu2-reference（参考图生视频，1–3 张）。
   Vidu 图片格式含 webp，单张最大 50MB，时长 4 或 5 秒（以官方文档为准）。
7. GLM-Image（智谱出图模型）只接受文字，没有参考图参数。

以下内容尚未核实，落地前必须先查官方文档：Wan 图生视频的模型名与请求字段、
Seedance 的多图参考方式、各出图模型"带参考图出图"的接口。

三、核心思路：先出图，再动起来

  分镜 -> 【新】分镜图阶段(frames) -> 【改】图生视频阶段(video) -> 【新】拼接阶段(concat)

1. 分镜图阶段（frames，新增）
   - 输入：storyboard.json 每个分镜的 frame（分镜图提示词，直呼角色名）、
           角色参考图（images/refs 阶段产物）、场景设定图（<地点>-sheet.png）。
   - 输出：output/frames/<段号>/f<切序>.png，与技能包约定的目录结构一致。
   - 关键：出图时把"角色参考图 + 场景图"作为参考图一起传入，
     而不是只传文字。这一步决定整条链路的一致性上限。
   - 不带参考图的出图模型（如 GLM-Image）做不到这一点。
     需要换成支持参考图的出图模型，或改用"编辑/合成"类接口。具体型号待核实后选定。
   - 每张图先人工快速过目，不合格的单张重出，再进入视频阶段。

2. 图生视频阶段（video，改造）
   - 单位：以"分镜"（cut）为单位生成，不再以"段"为单位。
     原因：每个分镜都有自己的分镜图，一图对一镜，最能锁定画面；
     CogVideoX-3 的 5/10 秒档位也和 2–10 秒的分镜更接近。
   - 三种模式，由 models.json 里每个视频模型的 input_mode 决定：
       t2v   文生视频：保持现状，作为兜底。
       i2v   图生视频：首帧 = 该分镜的分镜图。
       flf   首尾帧：首帧 = 本分镜图，尾帧 = 同段下一个分镜图（同场景时使用）。
     推荐默认 i2v；同一场景内需要镜头衔接时用 flf。
   - 提示词：图生视频不需要再描述外观，只写"怎么动"。
     取分镜的 shot（运镜 + 主体动作 + 位置变化）和 camera 字段，去掉角色名，
     控制在 512 字符内（CogVideoX-3 的上限），台词不写进提示词。
   - 图片传入：本地 PNG 转成 Base64（data URI）提交；超过 5MB 先压成 JPEG。
   - 画幅：由分镜图的实际尺寸决定，保证与分镜图一致，不再硬写 1920x1080。

3. 拼接阶段（concat，新增，可后做）
   - 用 FFmpeg 按段号、切序拼接各分镜视频，按分镜秒数裁切到目标时长
     （CogVideoX-3 只给 5/10 秒，需要裁切）。
   - 台词配音走单独的 TTS 轨，不依赖视频模型出声。

四、manifest（video-manifest.json）需要新增的字段

每个条目增加：mode、first_frame、last_frame、image_inputs、cut_id、target_seconds、
actual_seconds、frame_check（frame 图是否通过人工确认）。
任务状态沿用 planned / submitting / polling / succeeded / failed，
续跑规则不变：已有 task_id 的任务只查原平台，避免重复计费。

五、保证一致性的手段，按效果从大到小排序

1. 分镜图出图时带角色参考图 + 场景图（最关键）。
2. 同一场景内用首尾帧模式，让相邻分镜的画面首尾对上。
3. 同一部戏固定画幅、固定出图风格词，不要中途换模型。
4. 视频生成后逐条质检，不合格的单条重抽，不重做整集。
5. 台词多的镜头尽量用反应镜头、背影、画外音，减少对口型的依赖。

六、需要提前知道的限制

1. CogVideoX-3 的 with_audio 只出音效，不保证台词和口型。
   需要对口型的镜头，要另选支持的模型，或后期配音处理。
2. 首尾帧模式只能用 speed 画质，画质可能低于 quality。
3. 首尾帧要求两张图构图相近，否则中间会"变形过渡"。
   不同场景的分镜之间不要用首尾帧。
4. 每个 5 秒以内的分镜也要付一个 5 秒的钱，分镜切得越碎越贵。
5. 提示词 512 字符的上限会丢信息，所以动作描述要写短。

七、分步落地计划

第 1 步：先核实"带参考图出图"的模型接口（候选和计费），选定一个出图模型。
第 2 步：实现 frames 阶段，先对 1 集的 3 个分镜试出图，人工看一致性。
第 3 步：改 video 阶段支持 i2v（Base64 首帧），先对 1 个分镜试生成，确认画面、时长、费用。
第 4 步：加 flf 模式，只在同场景相邻分镜里使用。
第 5 步：加 concat 阶段和质检清单。
第 6 步：补离线测试（用本地假接口覆盖 i2v / flf 请求体、Base64 超限压缩、断点续跑）。

八、验收标准

- 同一角色在同一集多个分镜里，脸型、发型、服装可以人工确认是同一个人。
- 同一场景的空间布局（门窗、家具位置）在相邻分镜里不乱。
- 预览模式不调用任何付费接口；提交模式支持只提交指定分镜。
- 失败的分镜单独重试，不影响已完成的分镜。

九、待你决定

1. 出图模型：是否已有支持"参考图"的出图接口？没有的话选哪家？
2. 视频模型：以 CogVideoX-3 为主，还是同时保留 Wan / Seedance 的图生视频？
3. 台词镜头：接受"视频只出音效 + 后期配音"，还是要求视频模型直接对口型？
4. 生成单位：按分镜（推荐）还是按段？

================================================================
分镜图（frames 阶段）：已实现
================================================================

一、三条命令（先不加 --frames-gen 是预览，只整理任务和参考图引用，不调用出图接口）

1. 单个分镜（编号 = 视频阶段的镜头 ID，E01-01-C01 = 第 1 集第 1 段第 1 个分镜）：
   python run_agent.py run --stages frames --frames-gen --frames-only E01-01-C01
   也可以写段号 E01-01（该段所有分镜）或 E01（整集），多个用逗号分隔。
2. 一集批量：
   python run_agent.py run --stages frames --frames-gen --eps 1
3. 全部批量：
   python run_agent.py run --stages frames --frames-gen

已出好的分镜图自动跳过；要重出，加 --force（配合 --frames-only 只重出选中的）。
出完后接视频阶段：
   python run_agent.py run --stages video --eps 1 --video-protocol i2v --video-model cogvideox3_zhipu --shots E01-01-C01 --video-submit

二、分镜图编号与存放

output/frames/<段号>/f<切序>.png，例如 output/frames/E01-01/f1.png。
f<切序> 就是该段第几个分镜；视频阶段首帧直接读这里。
清单：output/frames/frames-manifest.json（每张图的提示词、参考图、状态、平台、错误）。
接口返回 jpg 时按 jpg 保存，视频阶段会自动识别 png / jpg / jpeg。

三、参考图引用规则

每个分镜自动引用，顺序固定，编号从 1 起：
  图1.. 该分镜 characters 里的角色图（来自 images 阶段的角色图）
  下一张  所属场景图（剧本该场 sceneId 对应的 art 场景图）
  最后    该分镜 props 里的道具图
提示词最前面自动加一段"参考图说明"，例如：
  参考图说明：图1是角色「徐今朝」的外观（脸型、发型、服装）；图2是场景「院子」的空间布局与光线……
然后才是分镜的 frame 提示词。参考图数量超过接口上限（max_references，默认 4）时，
角色优先，后面的丢弃并写进清单的 missing_references。
某个角色/场景/道具还没有参考图时，清单里会写明缺哪张，不会假装引用了；
先运行 images 阶段补出这些图，再出分镜图，一致性才有保证。

四、配置：不需要新增

分镜图和角色图、场景图共用 models.json 的 image 号池（同一个接口），不另设配置。
请求体和角色图、场景图一致（model / prompt / size / n / quality），只多一个参考图字段：
  "image": [参考图1, 参考图2, ...]     // Base64 data URI，默认字段名 image
平台的参考图字段写法不同时，在 image 条目里按需追加这些可选字段（都不必填）：
  "sizes": {"16:9": "1536x1024", "9:16": "1024x1536"}   // 竖屏剧按画幅选尺寸，没有就用 size
  "reference_field": "image"            // 参考图放在哪个字段
  "reference_style": "list"             // list | single（只传第 1 张）| objects（[{"image_url": ...}]）
  "image_encoding": "data_uri"          // 或 base64
  "max_references": 4                   // 最多传几张
  "request_template": {...}             // 请求体整体特殊时才用，可用 {{model}} {{prompt}} {{size}} {{quality}} {{images}} {{image}}

五、需要你确认的事项

1. 先小额试跑：用单个分镜命令出 1 张，看日志打印的请求体（参考图只显示文件名）和出图效果。
   如果接口报参考图字段错误，把完整错误发我，通常只要在 image 条目里加 reference_field / reference_style。
2. 响应格式沿用角色图、场景图的解析（data[0].b64_json 或 url），不需要改。
