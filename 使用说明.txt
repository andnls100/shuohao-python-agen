shuohao-python-agen 视频生成最新使用说明

================================================================
一、视频生成逻辑
================================================================

视频生成单位 = 一个分镜头 cut，例如：E01-01-C01。

1. 第一镜 / 新场景 / 明确切断

固定场景：
  场景图 + 角色参考图 + 道具参考图 + 当前镜头提示词

非固定场景：
  角色参考图 + 道具参考图 + 当前镜头提示词

2. 连续镜头

只有同时满足：
  - 同一集
  - 同一 sceneIndex
  - 当前 cut.continuity.mode == "inherit"
  - 当前 cut.continuity.referenceFrame 明确指向紧接着的上一镜
  - 如果跨 segment，则当前 segment.continuityMode == "continuous"

才使用：
  上一个视频的真实最后一帧 + 角色参考图 + 道具参考图 + 当前镜头提示词

3. 以下情况绝不继承上一镜最后一帧：
  - hard_cut
  - cut
  - 换场 / sceneIndex 改变
  - referenceFrame 缺失
  - referenceFrame 指向的不是紧接上一镜
  - 跨 segment 但没有 continuityMode == continuous

注意：同一个 sceneIndex 不代表连续镜头。程序以 storyboard 的 continuity 字段为准。

================================================================
二、最重要的命令
================================================================

1. 只生成单个镜头的视频计划，不调用视频 API：

python run_agent.py run --stages video --eps 1 --shots E01-01-C01

2. 提交第一个镜头：

python run_agent.py run --stages video --eps 1 --shots E01-01-C01 --video-submit

3. 提交下一个连续镜头：

python run_agent.py run --stages video --eps 1 --shots E01-01-C02 --video-submit

如果 C02 是连续镜头，程序必须先确认 C01 已成功，并确认 C01 的真实最后一帧存在。
没有最后一帧时，C02 直接拒绝提交，不会错误退回文字生视频。

4. 整集按顺序生成：

python run_agent.py run --stages video --eps 1 --video-submit

程序逐镜生成：上一镜完成 → 下载 → FFmpeg 提取最后一帧 → 判断下一镜 → 提交下一镜。

5. 指定多个镜头：

python run_agent.py run --stages video --eps 1 --shots E01-01-C01,E01-01-C02 --video-submit

5.1 按段生成（该段全部镜头按顺序逐镜生成，可多段，逗号分隔）：

python run_agent.py run --stages video --eps 1 --segments E01-01 --video-submit
python run_agent.py run --stages video --eps 1 --segments E01-01,E01-02 --video-submit

5.2 合并调用（默认开启）：同一段内、与上一镜连续（continuity=inherit 且引用上一镜）的镜头合并为一次视频调用，总时长不超过 10 秒；
    新场景/硬切/跨段非连续的镜头不会合并。合并后的 ID 形如 E01-01-C01-C02，--shots 写其中任一镜头 ID 即可。

不合并（逐镜头一次调用）：python run_agent.py run --stages video --eps 1 --segments E01-01 --video-merge-seconds 0 --video-submit
改上限为 8 秒：  python run_agent.py run --stages video --eps 1 --segments E01-01 --video-merge-seconds 8 --video-submit

说明：每个镜头是否接上一镜最后一帧，始终按整集顺序判断；段首镜头若与上一段连续，需上一段最后一镜已生成，否则报错提示先生成。

6. 只预览 Seedance 风格提示词：

python run_agent.py run --stages video --eps 1 --video-protocol seedance

默认协议：h3，直接使用 storyboard 的 h3Prompt。

================================================================
三、连续性判断示例
================================================================

例 1：同一场连续

E01-01-C01
E01-01-C02

C02：
  continuity.mode = inherit
  continuity.referenceFrame = E01-01/f1.png

=> C02 使用 C01 视频真实最后一帧。

例 2：同一场但硬切

E01-01-C01
E01-01-C02

C02：
  continuity.mode = cut

=> C02 不使用 C01 最后一帧。

例 3：跨 segment 但同一场连续

E01-01-C02
E01-02-C01

E01-02：
  continuityMode = continuous
  C01.continuity.mode = inherit
  C01.continuity.referenceFrame = E01-01/f2.png

=> E01-02-C01 使用 E01-01-C02 视频真实最后一帧。

例 4：换场

E01-01-C02 -> sceneIndex=1
E01-02-C01 -> sceneIndex=2

=> 不继承上一镜最后一帧；重新使用新场景图（如果有）+ 角色/道具参考图。

================================================================
四、最后一帧在哪里
================================================================

视频成功下载后：

output/video/last-frames/E01-01-C01.png

这是下一连续镜头真正使用的首关键帧。

不再使用：
  output/frames/<段号>/f<切序>.png

静态 frames 阶段仍可独立运行，但不再决定视频连续性。

================================================================
五、video-manifest.json
================================================================

output/video/video-manifest.json 每个镜头包含：

  input_mode
    scene_or_assets / previous_last_frame

  continuity_decision
    程序实际采用的连续性判断结果

  previous_shot_id
    当前镜头依赖的上一镜

  scene_fixed
    是否找到可用场景图

  initial_reference
    scene_reference / previous_last_frame / none

  last_frame_path
    当前视频真实最后一帧

================================================================
六、模型要求
================================================================

新的设计要求视频模型支持参考图 / 图生视频输入。
当前代码对 Wan R2V 的支持最完整：

  adapter = aliyun_wan
  mode = r2v

R2V 参考媒体顺序：
  1. 连续镜头：上一视频真实最后一帧（本镜首关键帧）
  2. 场景图（固定场景时）
  3. 角色参考图
  4. 道具参考图

总参考图数量不能超过模型接口允许的上限。

================================================================
七、models.json 示例
================================================================

{
  "video": [
    {
      "key": "wan-r2v",
      "name": "Wan R2V",
      "adapter": "aliyun_wan",
      "mode": "r2v",
      "submit_url": "https://your-provider.example/v1/videos/generations",
      "status_url_template": "https://your-provider.example/v1/tasks/{task_id}",
      "api_key_env": "VIDEO_API_KEY",
      "model": "your-r2v-model"
    }
  ]
}

实际 URL、模型名、请求字段和鉴权方式必须按供应商官方接口填写。

================================================================
八、旧命令
================================================================

以下命令已经删除：

  --video-protocol i2v
  --frames-dir
  --video-flf

原因：旧逻辑依赖静态分镜图作为视频首帧，并不能实现“上一段视频真实最后一帧 → 下一段视频首关键帧”的连续链路。

================================================================
九、FFmpeg
================================================================

必须安装 FFmpeg，并保证命令：

  ffmpeg

可以直接在终端执行。

分镜时长（每个镜头 4–8 秒，默认）：
- 默认 minCutSeconds=4、maxCutSeconds=8（每段 9–15 秒不变）。
- 临时改范围，不改代码：设置环境变量 AGENT_STORYBOARD_PARAMS，例如
  Windows PowerShell:  $env:AGENT_STORYBOARD_PARAMS='{"minCutSeconds":2,"maxCutSeconds":10}'
- 改完时长规则后需重新切分镜：python run_agent.py run --stages storyboard --eps 1 --force
